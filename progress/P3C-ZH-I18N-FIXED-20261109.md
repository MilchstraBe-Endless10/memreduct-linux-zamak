## P3C：跨进程面板漏译修复并中文实测通过

2026-11-09。发现并修复一处真实的 i18n 缺陷。

### 缺陷

跨进程候选面板与确认页有 5 处**硬编码英文**，不经过 `label(s.zh, …)`：

- 候选行 `… private regions · … resident estimate`
- `Application: …`
- `Request … · RSS …`（两种模式各一处）
- `Private resident: …`

中文模式下这些字样仍是英文。注意 `xproc_candidate_state_text` 本身是双语的
（`running/运行中` 等），问题只在外层包装的固定词。

### 修复

5 处全部改为 `label(s.zh, en, cn)`，中文分别为：

- `私有区域 N 个 · 常驻估计 …`
- `应用：…`
- `请求 … · RSS …`
- `请求 … · 作用域 匿名+文件 …`
- `私有常驻：…`

### 验证

`zam check .` → CHECK OK；`python3 -m unittest discover -s tests` → 246 通过 / 1 跳过。
重建 `m0+m1-candidate`（sha256 `8dbf39e1fd7e97a7e1dbbf1ea6531e5b9d5cca5705e200598ad84c0635691eb1`），
在 Xvfb 下以中文偏好启动，截图确认：

- 菜单栏：`文件 / 视图 / 设置 / 帮助`
- 分组：`物理内存`
- 面板：`仅一个手动选择的进程；helper 会重新核验身份` / `仅供预览；建议量不等于释放量。`
  / `PAGEOUT 可能占用 swap/I/O 并使目标卡顿。`
- 候选行：`休眠中 · 私有区域 27 个 · 常驻估计 16 KB`
- 按钮：`刷新 / 继续…… / 关闭`，底部 `清理内存`

### 排查过程中撞到的两个坑（记下来免得重复）

1. **应用目录必须是 `0700`**，`0755` 会被判 `MR_PREFERENCES_OWNERSHIP_OR_MODE`（load_status=6），
   于是 `main()` 里 `if status == 0 or status == 1` 不成立，语言永远回落到英文。
2. **`language` 的值是字符串 `en` / `zh-CN`**，不是数字。我先试了 `language=1`，
   解析器判 `CORRUPT`（load_status=2）。

这两个坑叠加时现象一样（界面全英文），极易误判为「偏好没接上」。

### 补记：上一轮只修了看到的 5 处，漏了 13 处

上一轮凭「读代码时注意到」修了 5 处，没有做系统扫描。这轮补上：

```
grep -n 'p.text(' src/main.zm | grep -E '"[A-Za-z]' | grep -v 'label('
```

一次查出**结果页还有 13 处**硬编码英文，全部在用户可见位置，包括几条关键术语：

| 位置 | 原文 | 中文 |
|---|---|---|
| 候选行 | `UID … · app …` | `UID … · 应用 …` |
| 确认行 | `Target PID … · UID …` | `目标 PID … · UID …` |
| 预算 | `Helper selected: … of …` | `helper 选定：… / …` |
| 统计 | `Regions: N · helper calls: N` | `区域 N 个 · helper 调用 N 次` |
| 观测 | `Target RSS: … → …` | `目标 RSS：… → …` |
| 观测 | `Target swap: … → …` | `目标 swap：… → …` |
| 原因 | `Reason: … · errno …` | `原因：… · errno …` |
| 观测 | `MemAvailable KiB: … → …` | `MemAvailable（KiB）：… → …` |
| 请求 | `memory.reclaim request: …` | `memory.reclaim 请求：…` |
| 作用域 | `Scope current/swap/anon+file` | `作用域当前/swap/匿名+文件` |
| 统计 | `Regions: N · calls: N` | `区域 N 个 · 调用 N 次` |

`Helper selected` 和 `Advised` 这两条是术语纪律的关键位置——中文用户看不到它们，
就没法判断「这是建议量还是释放量」。所以这不是纯装饰性问题。

### 方法上的教训

**「读代码时顺手发现几处」不等于「查全」。** i18n 漏译这类问题必须用机械扫描
（`grep` 找出所有不经 `label()` 的含字母文本），不能靠眼力。
上一轮修 5 处就提交，等于把一个本可以一次做完的活分成了两轮，
还让中文用户可以在一轮里看到混合语言界面。
