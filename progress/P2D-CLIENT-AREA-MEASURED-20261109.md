## P2D：客户区几何实测 = 337×369，与源码断言一致

2026-09-11-09，Xvfb + 已安装生产版 GUI。此前几轮只量了窗口总高 415，
这一轮把「内容区到底多大」测实。

### 实测数据

| 层 | 值 | 依据 |
|---|---|---|
| 窗口总尺寸 | **337×415** | `xdotool getwindowgeometry` / `xwininfo` 一致 |
| GTK CSD 标题栏 | **46 px**（y=0..45） | 像素扫描：y=46 起为菜单栏首行（`menu_bar_item_rect` 索引 1 在 canvas y=1） |
| 内容区（客户区） | **415 − 46 = 369 px** | 与 `main_window_height_px() == 369` 一致 |
| 内容区宽 | **337 px** | 与 `main_window_width_px() == 337` 一致 |

### 关键点：46 px 是 GTK 自绘，不是窗口管理器装饰

截图可见标题栏在窗口内部绘制了 `Mem Reduct` 标题与 `_ □ ×` 三按钮。
所以 Xvfb 没有窗口管理器的情况下这 46 px 依然存在——
这也解释了早前「337×415 是不是被 WM 加了两层标题栏」的疑问：**没有重复标题栏**。

### 像素证据

逐行灰度均值（337×1 条带）：

```
y=44..49  mean≈215    ← 标题栏底部
y=50      mean=186    ← 菜单栏下边框
y=51+     mean=254    ← 菜单栏背景
```

我一开始把 y=50 那道边框误当成内容区起点，算成 365 px；核对
`menu_bar_item_rect(1) = rect(4.0, 1.0, 40.0, 21.0)`（canvas 坐标）后确认
41..67 这段是菜单栏，标题栏只占 0..45 —— 修正为 369 px。
