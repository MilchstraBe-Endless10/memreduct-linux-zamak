## P3D：托盘功能现状 —— 完全未实现（必须如实披露）

2026-09-11-09。用上游 RC 核对菜单树时，发现托盘这块是个大缺口。本轮专门查清并记录。

### 上游 `IDM_TRAY`（resource.rc:57-90）

结构相当完整：

```
POPUP ""
{
    IDM_TRAY_SHOW
    SEPARATOR
    IDM_TRAY_CLEAN
    SEPARATOR
    POPUP ""  { 8 项：工作集 / 系统文件缓存 / 已修改文件缓存 /
                备用列表优先级0 / 备用列表 / 已修改列表 /
                注册表缓存 / 合并内存列表 }
    POPUP ""  { IDM_TRAY_DISABLE_1 / SEPARATOR / ... }
    ...
}
```

### 本项目现状

```
grep -c 'tray' src/main.zm     → 0
grep 'status_icon|GtkStatusIcon|libappindicator|notify' src/ native/  → 无任何实现
```

`tray` 字样只出现在两处**与运行时无关**的地方：

1. `settings_resources.zm` 里托盘设置页的**控件描述字符串**
   （`"SettingsProc: TrayUseTransparency default FALSE"` 这类，是布局数据）
2. `settings_resources.zm:332` 一个叫 `tray` 的**局部数组变量**，装的是控件 id 列表

### 结论

| 层 | 状态 |
|---|---|
| 托盘图标本身 | **不存在**（没有 GTK status icon / appindicator） |
| 托盘右键菜单 | **不存在**（上游那 4 个弹出菜单、十几个项都没有） |
| 托盘设置页 | 存在，5 个页面之一，控件按上游资源表绘制 |
| 设置页里的托盘选项 | 绘制为 **disabled**，不可操作 |

也就是说：**设置页能配置一个并不存在的功能。**

### 这是不是缺陷

不是 bug，是**未实现的功能**。但它带来一个诚实性问题：

用户打开设置 → 托盘图标页 → 看到"颜色指示阈值""鼠标单击行为"等选项，
虽是灰色不可点，但仍会以为"这个功能存在、只是被暂时禁用"。

真实情况是**根本没有托盘**，那些设置永远不会生效。

### 与其他已知未实现项的关系

同类情况目前确认有：

| 功能 | 状态 |
|---|---|
| 帮助 → Website / 检查更新 / 关于 | 菜单项在，点击只显示"尚未实现" |
| 托盘图标与托盘菜单 | 设置页在，运行时完全不存在 |
| 冻结/中止进程、注册表缓存等 Windows 专有项 | 设置页有控件，已禁用 |

第二项的区别在于：**前者点击后有明确反馈，后者连入口都没有**。
用户即使想用也没法用，只能从设置页的灰色控件推断"可能没做"。

### 顺带：Wayland 托盘的技术约束

在 Wayland 下 GTK3 的 `GtkStatusIcon` 已废弃且多数合成器不支持，
通常需要 `libappindicator` / `StatusNotifierItem`（依赖 D-Bus 与宿主实现）。
Hyprland 需要 waybar 带 tray 模块才显示。这意味着**即使实现，也依赖用户环境**，
不是纯粹的应用侧工作。

这条应作为做托盘功能的前置调研结论。
