## P2C：全量双语对照审计 —— 60 对里 4 处中文多带说明

2026-09-11-09。上一轮发现「气泡提示」中文多带「Windows 通知」，
本轮不再凭印象判断，而是把 `settings_ui.zm` 里**全部** `text(zh, en, cn)` 抽出来做机械对照。

### 方法

```python
pat = re.compile(r'text\(zh,\s*"((?:[^"\\]|\\.)*)"\s*,\s*"((?:[^"\\]|\\.)*)"\)')
# 比较两侧括号数量：中文括号多于英文 → 信息量不对等
```

共 **60 对**，其中中文侧括号多于英文侧的 **4 处**：

| 行 | 英文 | 中文 |
|---|---|---|
| 435 | `Start minimized` | `最小化启动（不显示窗口）` |
| 437 | `Skip "User Account Control" prompt warning` | `跳过"用户账户控制（UAC）"提示` |
| 489 | `Use transparent background` | `使用透明背景（不显示颜色提示）` |
| 524 | `Balloon tips:` | `气泡提示（Windows 通知）:` |

### 这 4 处分属两类，不能同一处理

**第一类（3 处）：补充说明，合理且应该保留**

- 435：英文 `Start minimized` 有个真实歧义——是最小化到任务栏，还是根本不显示窗口？
  中文用「（不显示窗口）」把这个歧义消掉了。**这是翻译质量的提升，不是缺陷。**
- 437：UAC 是缩写，中文补全「用户账户控制（UAC）」，两种语言都给了全称和缩写。合理。
- 489：透明背景下颜色提示不可见，中文说明了这个副作用。合理。

这三处**不需要动**。若为了"两侧对齐"而删掉中文括号，是倒退。

**第二类（1 处）：能力缺失，需要双向补全**

- 524：`Balloon tips` 在 Linux 上根本无法工作。中文说了"这是 Windows 通知"，
  但没说"Linux 不支持"；英文什么都没说。

### 关键区分

前 3 处是**语言层面的翻译增益**（把英文的歧义或缩写讲清楚），
第 4 处是**平台能力层面的诚实性问题**（控件在 Linux 上不可用）。

两者在代码里长得一模一样，都是"中文括号比英文多"，
但性质完全不同。**机械扫描能找出候选，判断性质必须逐条读语义。**

这也修正了我上一轮的过度概括：我一度以为"中文系统性多带说明、说明维护者偏好在括号里补信息"，
进而推演出"那气泡也该补 Linux 说明"。更准确的说法是：
维护者**在需要澄清时会加括号**，气泡那处的括号说明澄清了"这是 Windows 的"，
却没澄清"Linux 上用不了"——这是同一个做法没做完，不是新方向。
