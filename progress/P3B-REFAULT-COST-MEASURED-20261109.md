## P3B：PAGEOUT 的真实代价——换出后再访问要慢 198~497 倍

2026-11-09。这是本轮最关键的一组数，因为它直接回答"清理内存要不要付出代价"。

### 实测（256 MiB 私有匿名区）

```
A resident_walk        =     0.47 ms      ← 页常驻时的基线
  bytes_paged_out      = 271069184        (≈258.5 MiB)
B walk_after_reclaim   =    92.24 ms      ← 换出后重新访问  → 慢 197.9 倍
C walk_again           =     0.55 ms      ← 页已回到内存
  bytes_paged_out(2)   = 271069184
D walk_after_reclaim2  =   231.37 ms      ← 再次换出后访问  → 慢 496.5 倍
```

### 怎么读

- **B vs C 的对比是决定性的**：同一块内存，换出后访问 92 ms，第二次访问 0.55 ms。
  差出来的 91.7 ms 全部是缺页读回的代价，不是访存本身。
- **D 比 B 更慢（231 vs 92 ms）**，因为本机 zram 已占用 14.9/15 GB，
  第一次换出的页大多进了 zram（快），第二次开始溢出到 `/swap/swapfile`（慢）。
  这不是代码问题，是 **swap 后端的分层效应**，值得单独记一笔。

### 对产品的意义

这就是为什么 README 和 UI 都必须说「PAGEOUT 可能占用 swap I/O 并使目标卡顿」。
不是免责声明式的官话，是实测：**让 258 MiB 冷页让出物理内存，代价是这些页再被访问时
要花 92~231 ms 而不是 0.5 ms。**

对本机尤其重要：`Mem: 15810 total / 1127 available`，`Swap: 31174 total / 20756 used`，
zram 已近满。在这种状态下对它做激进 PAGEOUT，会把页推进更慢的后端。

### 口径

本文所有回收结论都同时报出 advised/accepted 量与**重新访问代价**。
不提代价只报"降了多少 MB"，等于只讲了一半。
