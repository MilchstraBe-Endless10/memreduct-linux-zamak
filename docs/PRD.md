# 产品需求与约束（PRD） v1.0

## 一句话目标
在 Arch / Omarchy 的原生 Linux 桌面提供像 Mem Reduct 一样容易操作的**主动内存管理工具**：点击就执行可说明、可验证的动作，清楚告诉用户动作做了什么、对性能可能有什么影响。

## 目标用户与主要场景
- 用户同时运行大型浏览器、创作软件、IDE、桌面服务，认为 RAM 吃紧。
- GUI 中文、没有 WebUI/Docker，不需要每次手写终端命令。
- 优先一键动作及结果，数字只是结果证据，不把监控作为产品目标。

## 功能需求
| ID | 功能 | 阶段 | 验收 |
|---|---|---|---|
| F-01 | 中文原生 GUI，真实内存数据 | P1/P2 | Wayland 下正常打开、刷新，不阻塞 |
| F-02 | 手动缓存回收：文件、元数据、组合 | P3 | 一次授权一次动作；显示退出码及前后数据 |
| F-03 | 透明的恢复影响说明与错误信息 | P2/P3 | 取消授权、无权限、不支持均可见 |
| F-04 | 可恢复设置与操作历史 | P4 | 有状态持久化和关闭机制 |
| F-05 | 可选自动执行和冷却保护 | P4 | 默认为关；不重复弹授权；可停用 |
| F-06 | ZRAM 只读状态及可选受控策略 | P5 | 检测现有配置、不暗中 swapoff |
| F-07 | Arch Linux 安装/卸载、发布包 | P6 | 可重装可卸载，回滚说明完整 |

## 非功能要求
- GPL-3.0-or-later，独立实现并保留 Henry++ 署名；依赖声明齐全。
- 低常驻资源；性能目标须实测，不得猜数字。GUI 禁 root，系统写操作封闭白名单。
- 对当前系统功能无需 KVM/Binder，也不需要 Android 虚拟化。
- 在提交前必须区分 Linux 页缓存回收与程序匿名内存压缩的技术机制。

## 特殊风险和约束
- 用户希望不影响软件运行：可以承诺**不主动杀进程**，但无法承诺对系统速度完全无影响。
- Linux 内核文档指出 drop_caches 不是日常性能优化建议，缓存重建可能增加 I/O 与 CPU。推荐默认的性能模式应该侧重 ZRAM、只读观察和按需回收，而非定时清空热缓存。
- 对需要 root 的后台自动化，必须先明确授权模型并经过安全验收。

## 版本边界
当前 v0.2.0 是原型，不是生产稳定版。P1 通过后可以标为开发预览；只有 P6 测试过后才考虑正式公开二进制。
